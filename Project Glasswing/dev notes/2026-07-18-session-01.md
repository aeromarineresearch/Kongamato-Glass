## 2. The product in one paragraph

**Project Glasswing** is an affordable, sleek, open-source EFIS for sport/hobby
pilots (E-AB/LSA, VFR-day, advisory-only — not certified). Target entry price
≈ **$350** vs Dynon/Garmin at $3–5k. Stack: **MakerPlane** pyEfis (displays) +
FIX-Gateway (data broker), **SpeedyBee F405 WING running ArduPilot** (AHRS/GPS/
air data), **ESP32 CAN-FIX sensor nodes** (engine monitoring, custom PCBs
later), **Raspberry Pi 5** (compute), and **Chronos-2** predictive analytics as
the differentiator nobody else ships. Full detail: `../MASTER-PLAN.md`.

### 5.2 Milestone 0 launcher — built, then debugged through 6 real bugs

**Bug 1 — RPi-only deps broke macOS install.** `make init` in FIX-Gateway
failed: `lgpio` needs `swig`, `smbus` needs `linux/i2c.h` — both Raspberry-Pi-only.
**Fix:** moved `rpi-lgpio`/`smbus` from hard deps to a `[rpi]` extra in
`pyproject.toml`; Makefile's Pi branch now installs `.[rpi]` (behavior on real
Pis unchanged). → part of patch **0001**.

**Bug 2 — mavlink plugin was serial-only.** It `stat()`ed the port device and
required a baud rate; SITL speaks MAVLink over UDP. **Fix:** patched
`Mav.py` (skip `stat()` checks for `udp:`/`tcp:` prefixes; connect without baud)
and the plugin `__init__.py` (accept `type: "network"`). → part of patch **0001**.

**Bug 3 — launcher not idempotent.** Re-runs after a failure tried to redo
setup. **Fix:** key setup off the `init.marker` file, not the venv dir.

**Bug 4 — pyEfis crashed instantly on `xwininfo`.** The default screen set
includes an **Android/Weston screen** that embeds Waydroid apps via the Weston
compositor and shells out to `xwininfo` — X11-only, doesn't exist on macOS.
`FileNotFoundError: 'xwininfo'` killed the whole app (symptom: dock icon
bounces forever, no window). **Fix:** patched
`pyefis/instruments/weston/__init__.py` to detect missing tooling
(`weston`/`xwininfo`/python-xlib) and render a "Weston unavailable on this
platform" placeholder instead of crashing. → patch **0002**.
*Deliberately did NOT remove the Android screen from the default list — the nav
buttons cross-reference it and removing it risks breaking button configs.*

**Bug 5 — syslog traceback spam.** FIX-Gateway's stock logging config has a
`SysLogHandler` pointing at `/dev/log` (Linux-only). Non-fatal but noisy.
**Fix:** launcher seds the seeded `config/fixgw/default.yaml`:
`handlers: [stderr, syslog]` → `handlers: [stderr]` (guarded, idempotent).

**Bug 6 — pyEfis opened fullscreen, no way to close/minimize.** pyEfis's
`screenFullSize: True` calls Qt `showFullScreen()` (cockpit-appliance mode).
**Fix:** in `src/pyefis/config/main/default.yaml` set `screenFullSize: False`
**and** `screenWidth: 1280` / `screenHeight: 800`. ⚠️ **Gotcha:** the
non-fullscreen code path (`gui.py`) does `int(config["main"]["screenWidth"])`
— width/height are **mandatory** when fullscreen is off, or it crashes.
→ patch **0003**. The launcher keeps the project's seeded copy in sync with
the repo file every run.

```yaml
  QUORUM: false
  DATA_RECORDER: false
  NETFIX: true      # serves the FIX db to pyEfis on TCP 3490
  COMMAND: false
  FLIGHT_GEAR: false
  XPLANE: false
  CANFIX: false
  MAVLINK: true     # reads SITL
  DEMO: false
```

### 6.2 `config/fixgw/connections/mavlink.yaml` (written every run)
```yaml
mavlink:
  load: MAVLINK
  module: fixgw.plugins.mavlink
  type: network                        # ← requires patch 0001
  port: "udp:127.0.0.1:14552"
  options:
    airspeed: true
    groundspeed: true
    gps: true
    ahrs: true
    accel: true
    pressure: true
    pascal_offset: 2800
```

### 6.3 Ports
| Port | Who | What |
|---|---|---|
| 14552/udp | SITL/MAVProxy `--out` → FIX-Gateway | MAVLink telemetry |
| 14550/udp | QGroundControl | unchanged default |
| 3490/tcp | FIX-Gateway NetFIX server → pyEfis | FIX data (ASCII protocol) |


## 9. Reference facts worth remembering

- **NetFIX protocol** (FIX-Gateway ↔ clients): ASCII sentences `ID;value;aobfs\n`,
  commands `@r/@s/@u`. An ESP32 could speak this over WiFi — alternative to CAN.
- **CAN-FIX:** CAN 2.0B, 11-bit IDs, 97 standardized params, payload
  `[NodeID][Index][Func/Status][5 data bytes]`.
- **ESP32 sensor nodes:** native TWAI/CAN + SN65HVD230 transceiver beats
  Mega+MCP2515; CAN-FIX Arduino lib ports with a `writeFrame` shim.
- **Chronos-2:** first real forecast downloads ~0.5 GB weights from Hugging
  Face; uses Apple Silicon `mps` backend automatically.
- Fault injection for the demo: `param set SIM_ENGINE_FAIL 1` in the MAVProxy
  console → the affected attitude channel should blow out of the forecast band.

```bash

#    (see research/ArduPilot-SpeedyBee guide), QGroundControl installed.

cd ~/DEV/Aviation/"Project Glasswing"/vendor/makerplane/repos

# 2. Clone the MakerPlane repos (all 11)
for r in pyEfis FIX-Gateway pyAvMap pyAvTools canfix-spec CAN-FIX-ArduinoLib \
         CAN-ArduinoLib EIS-R1 EFIS-Hardware-7-inch faa-cifp-data Documentation; do
  git clone "https://github.com/makerplane/$r.git"
done

# 3. Apply the three patches (they are in Project Glasswing/patches/)
P=~/DEV/Aviation/"Project Glasswing"/patches
(cd FIX-Gateway && git apply "$P/0001-mavlink-network-links.patch")
(cd pyEfis      && git apply "$P/0002-weston-graceful-degradation.patch")
(cd pyEfis      && git apply "$P/0003-pyefis-windowed-dev-mode.patch")

# 4. Restore research/ (ArduPilot-SpeedyBee guide, Chronos-2 starter) — from backup.

# 5. Restore the two launchers + READMEs (milestone0/, milestone1/) — from backup
#    or re-derive from §6 of this file.

# 6. Run. The launcher does everything else: venvs, config seeding/migration,
#    macOS patches, startup, cleanup.
bash ~/DEV/Aviation/"Project Glasswing"/milestone0/run-glasswing-sim.sh
```

**If patches fail to apply** (upstream moved on), re-derive manually from §5:
the three changes are (a) RPi deps → `[rpi]` extra, (b) `Mav.py`/`__init__.py`
network-link support, (c) Weston try/except-style guard + (d) windowed-mode
